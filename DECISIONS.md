# Решения

## Дата отчёта — включительно

- **Что решали:** как трактовать «отчёт на дату».
- **Варианты:** строго до даты (`<`) или включая день (`<=`).
- **Выбрал:** включительно (`paid_at <= as_of`, `completed_at <= as_of` и т.д.). Так обычно читают «на 10.11».
- **Если неверно:** платежи и статусы работ ровно на граничную дату попадут/выпадут из отчёта.

## Какие платежи считаются «выплачено»

- **Что решали:** `paid` / `queued` / `refunded` на дату.
- **Варианты:** считать queued уже выплаченным; всегда игнорировать refunded; учитывать refunded по статусу выгрузки без дат.
- **Выбрал:**
  - `paid` — только если `paid_at <= as_of`;
  - `queued` — не входит в «выплачено» (деньги не ушли);
  - `refunded` — входит только пока деньги ещё у подрядчика: `paid_at <= as_of` и `refunded_at > as_of`; после возврата — не входит.
- **Если неверно:** изменится сумма «выплачено» (в т.ч. P-2, P-4, P-8 на контрольной дате).

## Статус работы на дату

- **Что решали:** брать статус из CSV как есть или восстанавливать по датам.
- **Варианты:** слепой статус выгрузки; реконструкция по `completed_at` / `cancelled_at`.
- **Выбрал:** реконструкцию: cancelled если `cancelled_at <= as_of`, иначе done если `completed_at <= as_of`, иначе planned. Выгрузка может быть новее даты отчёта (пример: W-23 принята 11.11, на 10.11 — planned).
- **Если неверно:** W-23 и аналоги попадут в другой порядок FIFO и другую цену обязательства.

## Цена отменённой работы

- **Что решали:** что показывать как «цену» и «осталось» для cancelled.
- **Варианты:** оставлять CSV-цену; обнулить обязательство.
- **Выбрал:** цена в отчёте = 0, в FIFO не участвует. Привязанные платежи всё равно показываем в «выплачено» по работе.
- **Если неверно:** по отменённым работам появится «осталось оплатить» или они заберут долю аванса.

## Разнесение платежей без `work_id`

- **Что решали:** как показать «за что рассчитались», если платёж только на договор.
- **Варианты:** пропорция по ценам; FIFO по дате принятия; не разносить и держать отдельным пулом.
- **Выбрал:** сначала зачесть платежи с `work_id`, затем пул договора FIFO: сначала `done` по `completed_at`, затем `planned` по `work_id`. На работу: `min(max(price - linked, 0), остаток_пула)`. Cancelled в разнесении не участвуют. Неизрасходованный пул — «неразнесённый остаток» на договоре.
- **Если неверно:** поменяется разбивка «выплачено» по работам; итог по договору (сумма платежей) останется тем же.

## Деньги без float

- **Что решали:** тип для сумм.
- **Варианты:** `float`, целые копейки, `Decimal`.
- **Выбрал:** `decimal.Decimal` с квантованием до копейки при выводе.
- **Если неверно:** возможны ошибки округления на больших суммах.

## Битые ссылки и неизвестные статусы

- **Что решали:** молча игнорировать или падать.
- **Варианты:** тихий skip; warning; жёсткая ошибка.
- **Выбрал:** `ValueError` при неизвестном `payment.status`, при `work_id` без работы в договоре и при пустых обязательных датах в CSV.
- **Если неверно:** на чистых данных ничего не меняется; на битых выгрузках отчёт не построится вместо молчаливого сдвига сумм.

## Формат вывода

- **Что решали:** куда писать отчёт.
- **Варианты:** только stdout; только CSV; оба.
- **Выбрал:** таблицы в stdout; опционально `--csv DIR` для файлов работ и договоров.
- **Если неверно:** поменяется только способ просмотра, расчёт тот же.
